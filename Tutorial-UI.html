Overview

An ontology is a structured, machine-understandable model that defines:

📦

Asset Types

The types of things that exist in a system

🏷️

Properties

The properties those things have

🔗

Relationships

The relationships between them

Why Ontologies Matter

  • ✔ Consistency across multiple data sources
  • ✔ Interoperability between systems
  • ✔ Automation and reasoning capabilities
  • ✔ Graph-based digital twin models
  • ✔ Visualisations that reflect the real world

🚆 Why Ontologies Are Useful in Digital Twin Creation

Digital Twins represent real-world entities digitally. To keep those twins structured, discoverable, and interconnected, an ontology ensures:

  • Consistency: Every Station must have a stationId
  • Validation: Detect a Train claiming to be on a non-existent Line
  • Reasoning: Find all trains arriving at stations with accessibility features
  • Visualisation: Map stations based on latitude/longitude

Getting Started

🧱 What Is an Asset?

In an ontology, an asset is a type of thing modeled in the real world. In DTDL (Digital Twin Definition Language), assets are defined as Interfaces.

🚉 Station

Represents a physical train station

Properties:
  • name
  • stationId
  • latitude
  • longitude

🚂 Train

Represents a moving vehicle with real-time telemetry

Properties:
  • lineId
  • timestamp
  • vehicleId
  • expectedArrival

📍 Route

Represents a sequence of stations in travel order

Properties:
  • routeId
  • direction
  • stationSequence

🎯 Line

Represents a metro/tube line

Properties:
  • lineId
  • name
  • colour

♿ AccessibilityFeature

Represents accessibility options like elevators, ramps

Enables:
  • Accessible route planning
  • Compliance dashboards

Basics

🔗 What Are Relationships?

Relationships connect assets together and turn the system into a graph. They define direction, target asset type, and meaning.

Station →
servedByLine
→ Line

"This station is served by this line"

Route →
onLine
→ Line

"This route belongs to this line"

Train →
servesRoute
→ Route

"This train is travelling on this route"

Station →
hasAccessibilityFeature
→ Feature

"This station includes this feature"

Why Relationships Matter

  • 🔍 Power network queries and data discovery
  • 📊 Support dependency analysis
  • 🎨 Enable graph visualisation
  • 🧠 Allow reasoning and inference

Tips & Tricks

✔ Validation in Digital Twin Ontologies

Validation ensures the system is correct, consistent, meaningful, and safe to query and visualise.

1

Structural Validation

Model-Level Checks

  • Syntax correctness
  • Valid DTMI identifiers
  • References point to existing types
  • Property types are valid
2

Semantic Validation

Ontology Meaning

  • Train references valid Route
  • stationSequence contains valid IDs
  • Operator operates at least one Line
3

Instance-Level Validation

Twin Graph Checks

  • Station connected to at least one Line
  • Route belongs to exactly one Line
  • Train location matches route
4

Telemetry Validation

Dynamic Data Checks

  • secondsToNextStop ≥ 0
  • expectedArrival ≥ timestamp
  • Train direction matches Route
